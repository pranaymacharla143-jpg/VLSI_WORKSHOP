# GitHub Repository Guide

## Recommended final layout

After adding the actual source files and reports, a complete repository may follow this structure:

```text
VSDBabySoC/
├── README.md
├── .gitignore
├── design/
│   └── rtl/                  # Copy actual RTL modules here
├── testbench/                # Copy actual testbenches here
├── constraints/
│   └── vsdbabysoc_synthesis.sdc
├── scripts/
│   ├── run_simulation.sh
│   └── inspect_sta_results.sh
├── reports/
│   ├── setup/
│   ├── hold/
│   └── corners/
├── screenshots/
└── docs/
```

Keep the source layout consistent with the actual project rather than moving files if the flow relies on fixed relative paths.

## Copy the actual source from Codespaces

In the existing Codespace terminal, the VSDBabySoC design directory was located at:

`~/Desktop/OpenROAD-flow-scripts/flow/designs/sky130hd/vsdbabysoc`

To copy the actual directory into a repository workspace, run a command like this after replacing `REPO_DIR` with the path to the repository you intend to publish:

```bash
REPO_DIR="$HOME/VSDBabySoC_GitHub_Repository"
cp -a ~/Desktop/OpenROAD-flow-scripts/flow/designs/sky130hd/vsdbabysoc \
  "$REPO_DIR/design/"
```

This preserves the original design folder. Inspect the copied contents before committing.

## Suggested Git workflow

```bash
git init
git add README.md docs screenshots scripts .gitignore
git status
git commit -m "Add VSDBabySoC project documentation and evidence"
```

After adding the real source files, stage and commit them separately. Configure your Git username and email if Git requests them.

## What not to commit

Avoid committing large temporary caches, editor swap files, generated databases, or entire PDK/library installations unless your project specifically requires them and redistribution is permitted. Keep important reports and waveforms when they are part of the requested deliverables.

## Before submission

- [ ] RTL and testbench files are present.
- [ ] Simulation command and dependencies are documented.
- [ ] The reported waveform was actually generated by the documented testbench.
- [ ] SDC and design configuration match the reported run.
- [ ] Raw STA logs support the numeric claims.
- [ ] Screenshots have captions and correspond to the described stage.
- [ ] The README clearly explains what is included and how to reproduce it.
